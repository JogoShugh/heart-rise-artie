# Plan: a deterministic script from a run's capture

Status: proposed, 2026-10-18; guards, four decisions and the lock file added the same day. Mockup: `github-task-generated.kts` and its `github-task-generated.pins.yaml`, generated by hand from the capture of
the live reasoned GitHub run (docs/reports/line-by-line/github-reasoned), as the tool would. spec/PLAN-ARTIE-SCRIPTS.md
step 5 (slot filling); spec/PLAN-LINE-BY-LINE-REPORT.md (the capture).

## What it does

`artie generate CAPTURE.yaml [--script SOURCE.kts] [--freeze] > NEW.kts`: a script with no model in it,
run with `artie run NEW.kts name=value …` against other resources: other owners, repositories, issues. Every
reason step becomes the act or follow it made, nested as the run nested; every value is an input, a value read
again from an earlier answer, or a constant, by the rules below. A person reviews the lines it marks, then keeps
it.

## The rules (deterministic; a tie is marked for review, never guessed)

1. **Inputs.** Each input the run read becomes one. With the run's script, its `val … by input(...)` line is
   copied as written: required, a default (an expression, such as `LocalDateTime.now()…`), or a question.
   Without one (words typed into heart-mcp), the capture's own record of each input: its question and default
   (capture change 4).
2. **A value's binding**, in this order:
   1. an input with that value: the input;
   2. text the script wrote literally (outside any `$slot` of the reason template): a constant (`"main"`, the
      titles);
   3. a member of an earlier answer: a variable, set in the block of the step that **brought it into the run**
      (the earliest selection step whose state holds it, never a block end's re-read), from its pointer, and
      read where it is used (`issue = state["number"]` in step 3's block);
   4. the reason words: a constant.
3. **Inside a string**, every slot value and input value is put back as its variable: `"fix-reasoned-$stamp.md"`,
   `"Relates to #$issue"`, `"Fixed in 1.2 by #$pull."`.
4. **A value the words don't give**, or only paraphrase (`squash` for "squashing", `Opened by a HEART script.` for
   "saying it was opened by a HEART script"): that step stays a `reason(...)` (decided). With `--freeze`, it is
   written as the act it made, its values constants, each marked `// review:` with the words beside it.
4a. **Literal text the words gave** (titles, messages, file content) is a constant (decided); `--inputs title,body`
   makes those inputs, the run's text their default.
5. **Two sources that tie** (two members of the same answer holding one value) take the first by the capture's
   order and are marked for review.
6. **Types** are the form's schema's (capture change 5): `"91"` the reasoner sent for an integer is written as the
   number it is.
7. **Waits and checks** are copied from the script's own lines (`until(tries = 20) { offers("github:merge") }`,
   `check("merged" eq true)`); without a script, from the capture (`waited.for`, the facts).
8. **Only a run that finished** is generated from; a refused or failed step stops the generator, saying which.
9. **What the run was offered is pinned beside the script**, never in it (decided: the script stays as it reads):
   `NAME.pins.yaml`, a lock file as Gradle's verification metadata and npm's lock are, found by the script's
   name (or `--pins FILE`). It holds the rung the run read at, and by relation: each form's own integrity
   (HAL-SCHEMA-FORMS-HR Rule 10, which covers its schema's) and every affordance set it was offered in; each
   link's target template (decided; links have no integrity). Keyed by relation, not by line, so editing the
   script never misaligns a pin, and a form's integrity is the same whichever resource offers it.

## Guards, when a generated script runs

`artie run --guard lenient|strict` (lenient by default, decided). Before sending anything, ARTIE checks the
selection against the lock file (spec/ideas/replay-guards-lenient-strict.md):

| Mode | Refused before anything is sent, when |
|---|---|
| lenient | the form is no longer offered, or its integrity is not the pinned one, in whatever set holds it now |
| strict | as lenient, or the set holding it is not among those recorded for it |
| both | a fetched body doesn't hash to its link's integrity (Rule 2, always) |

A refusal is a new kind, "guard": by the client, naming the pinned and the offered integrity. A run at another
rung than the lock file's says so before its first request. A kept reason step whose model chooses a relation
the lock file doesn't hold: lenient goes on and the capture marks it unpinned; strict refuses it.

## Capture changes first (each test first)

0. The bookmark's lookup forms carry their own integrity (Rule 10): the index builds them outside
   `Layers.form`, so the capture of every lookup from the bookmark has no form integrity, and nothing to pin.

1. A check's facts are not values: no sources for them.
2. A block end's re-read is no source and keeps nothing: only selection steps bring a value into the run.
3. Words match case-insensitively and by word stem ("squash" in "squashing"), marked `words (paraphrase)`.
4. Each input keeps its question and its default as declared, beside its value and how it was given.
5. Each value sent keeps its type from the form's schema.
6. Earlier answers' embedded resources are searched too, by pointer into `_embedded` (`/user/login`).

## The proof

- **Same requests.** The generated script, run against the fake GitHub, writes a capture whose steps make the
  same selections, in the same order and nesting, with the same values, as the capture it came from (a capture
  comparison, which the line-by-line report can show).
- **Guards hold.** Against the fake GitHub: one form's schema changed, and the generated script stops before
  sending, lenient or strict; only another form of the same set changed, and lenient goes on, strict stops.
- **Other resources.** Run against the fake GitHub as another owner and repository (`acme/rockets`), and live
  against the scratch repository, where every run opens a new issue and pull request: no model, no tokens.

## Work

1. The capture changes, in heart-script (features with the scripted service), and the index forms' integrity in
   heart-core.
2. The lock file: read by artie run beside the script (or `--pins`), handed to the client with the run's
   settings, checked by ARTIE before every act and follow; `--guard`; the refusal kind (heart-script, artie,
   artie-cli; features first). The DSL does not change.
3. `artie generate` in artie-cli: features first, from captures the features write (scripted service), the
   mockup's script as the expected output for the reasoned GitHub capture.
4. The capture comparison and the replay against the fake GitHub (artie feature, in-process gateway).
5. Live: generate from the reasoned and hybrid GitHub captures, run each generated script (with `--freeze`, no model; without, a model only on its kept reason steps), report
   both runs line by line beside the runs they came from.
6. The idea's open item, what a lenient run reports when it acts on an unchanged form in a changed set: a warning
   in the capture and the report, with both set integrities.
