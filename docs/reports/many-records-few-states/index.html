HEART · employees service · 3 November 2026

Many Records, a Few States

One goal over many employees, each in one of three states. A kept script branches on what the server offers each record, so the model and the forms it needs follow the states, not the number of records.

In short

  • Four clients, 15 runs each: 5 runs at each group size, 6, 30 and 90 employees. 60 runs in all, and every one moved every employee correctly.
  • ARTIE's kept script used no model at any size, and fetched 3 form sets a run, one per state, for 6 employees or 90.
  • Without a case for a state, the model is asked for each record in it: with the give-notice case alone, 2, 10 and 30 calls. Keeping that case after the first time (not built yet) takes it back to none.
  • Code mode writes a loop, so its tokens per run hardly grow with the number of employees: about 10k on endpoints, 24k to 36k on HAL-FORMS alone. It pays them in every run, with a sandbox.

The goal, as every client was given it: "Move every employee named Miller one step through leaving: give notice to anyone working, dismiss anyone on notice, and leave the dismissed as they are." (Miller is the surname every test employee was given, so a search by it finds them all.)

The employees service with its notice release. Before each run the test employees are seeded through the service's own acts: as many working, on notice and dismissed.

How ARTIE's kept script works

flowchart TD
  S(["1 Search by surname"]) --> E["2 Each employee in the list"]
  E --> O{"3 What does it offer?"}
  O -- "give notice" --> G["act: give notice"]
  O -- "dismiss" --> D["act: dismiss"]
  O -- "nothing" --> N["4 note: left as is"]
  1. One search, as the server offers it, by name.
  2. whenever visits each member of the list, by its link.
  3. when-offered takes the first case whose act the employee offers now. The server decided its state; the script only reads the offer.
  4. An employee that offers none of the cases takes otherwise, with no model.

The scripts

The scripts search for the test employees by their surname, Miller (name: Miller). Both written by hand, as artie generate would write them from a goal run: the first from one that met both states, the second from one that met only those working. Generate writing when-offered itself is the next build.

artie/t5.kept.heart.yaml: a case for each state
# Written by hand as artie generate would write it from a goal run that met both states (spec/PLAN-COST-FOLLOWS-
# STATES.md: generate writing when-offered is not built yet). Each member is moved by what the server offers it:
# give notice where that is offered, dismiss where that is; otherwise it is left as it is.
#   artie run t5.kept.heart.yaml
heart: 1
kind: kept
start: http://localhost:8099/

steps:
  - act: staff:search-employees
    fields:
      name: Miller
    intent: Find the employees named Miller
    then:
      - whenever:
          - when-offered:
              - act: staff:give-notice
                intent: Give notice to anyone working
                then: []
              - act: staff:dismiss
                intent: Dismiss anyone on notice
                then: []
            intent: Move this employee one step through leaving
            otherwise:
              - note: ${state.firstName} ${state.lastName} is left as is

Code mode on HAL-FORMS: its last program, at 90 employees a loop it wrote, its fourth try 
import os,urllib.request,json,collections
b=os.environ['API_BASE'];t=os.environ['API_TOKEN']
H={'Authorization':'Bearer '+t}
def g(p):
    r=urllib.request.urlopen(urllib.request.Request(b+p,headers=H));return json.load(r),r.headers['ETag']
items=[];p='/employees?name=miller'
while p:
    d,_=g(p);items+=d['_links']['item'];n=d['_links'].get('next');p=n['href'] if n else None
res=collections.Counter();errs=[]
for i in items:
    e,et=g(i['href'])
    k={'working':'giveNotice','on notice':'dismiss'}.get(e['status'])
    if not k: continue
    tp=e['_templates'][k]
    h=dict(H);h['If-Match']=et
    data=None
    if tp.get('contentType'): h['Content-Type']=tp['contentType'];data=b'{}'
    try:
        r=urllib.request.urlopen(urllib.request.Request(b+tp['target'],data=data,method=tp['method'],headers=h));res[(k,r.status)]+=1
    except Exception as x:
        res[(k,str(x))]+=1;errs.append(x.read())
print(res,errs[:2])
c=collections.Counter()
for i in items: c[g(i['href'])[0]['status']]+=1
print(c)
  • It decides each employee's state from its status member, then takes the matching form's target and method from _templates, with the ETag it read.
  • Its earlier programs in the run wrote without If-Match (428) or dismissed with the wrong method (405); the server refused them, and nothing wrong was written.

  • The cost follows the states, not the records. Employees in the same state share one form set, fetched once a run; the kept script asks no model at any size.
  • A state with no case costs a model call per record. That is what keeping a new case once is for: the one-case run would then cost 1 call, then none.
  • Requests grow with the records for every client. ARTIE reads each employee and returns to the list, revalidating as it goes; code mode on endpoints reads less.
  • At 1,000 runs of 90 employees, projected: code mode about 10 million tokens on endpoints and 35 million on HAL-FORMS alone; ARTIE's kept script none, after the run that found its way.
How it was run bench, seeding, files
  • Bench: exhibits/mcp-over-openapi/bench.py --arms artie-data,artie-grow,code-fresh,code-heart-noapi --tasks t5 --reps 5 --population N,N,N, for N of 2, 10 and 30. Sonnet 5.5; code mode had 16 turns and the sandbox of the other runs.
  • Seeding: the notice release on (PUT /_sim/employees/changes), then each employee hired, given notice and dismissed through the service's own acts, before the measured requests.
  • Names: the test employees' surname is shown here as Miller; the run files use the surname the runs were seeded with.
  • Right: every employee moved one step (working to on notice, on notice to dismissed), the dismissed left, and no one else touched.
  • Files: runs/states-2.jsonl, runs/states-10.jsonl, runs/states-30.jsonl; ARTIE's traces in runs/artie/.
  • The plan: spec/PLAN-COST-FOLLOWS-STATES.md. The release-through-change runs: Wayfinding Through Change.
Limits said plainly
  • ARTIE's kept scripts were written by hand; the cost of the goal run that would find the way is not in these figures.

  • The test employees are seeded the same way each run, so each run meets the same states in the same proportions.
