How it was recorded

  • A second gateway, the same build as every other run's, served this run on its own port. Two small recording proxies stood in the two conversations: one between ARTIE and the gateway, one between the gateway and api.github.com. Each wrote every exchange as it passed: method, address, headers, body, status, time.
  • GitHub's answers are recorded as GitHub sent them. Before passing one on, the proxy wrote its own address for https://api.github.com in it, so the gateway knew the addresses as its own upstream's; nothing else was changed.
  • Credentials are recorded as <token>: ARTIE's bearer to the gateway, and the same bearer, passed on, to GitHub.
  • ARTIE entered the gateway at the recording proxy (--entry http://localhost:8393/); the script names the usual gateway, on 8392. Everything else is the script as it is.
  • Not recorded: the exchange between ARTIE and Claude (HTTPS to api.anthropic.com). What Claude was asked is each step's words; what it chose is each step's relation and values, as ARTIE checked and sent them.
  • The GitHub pages were taken after the run, signed out, in a headless browser: they show the repository as it is now.

Of the 77 GitHub requests, 7 are writes. The rest are reads the gateway makes to answer ARTIE: the resource asked for, and again before each act, to check ARTIE's If-Match against it; and, for an issue, a comment or a pull request, the two answers the connector's reader rules decide its offered acts from: the repository, for the caller's permissions (24 reads in all), and the signed-in user, to tell whether the caller wrote it (12 reads; issue.reader.yaml, comment.reader.yaml, pull.reader.yaml). 53 of them were answered 304 Not Modified, which GitHub does not count against the rate limit.

The script

 1  // The GitHub task, reasoned: each move said in words; the model chooses the form or link and its fields from what
 2  // the gateway offers, and ARTIE checks each choice before sending it. The same task as github-task-scripted.kts.
 3  // Needs --reasoner claude. Real writes, to the repository given.
 4  //   artie run tests/github-task-reasoned.kts owner=JogoShugh repo=heart-github-test --reasoner claude
 5  val owner by input()
 6  val repo by input()
 7  val stamp by input(default = java.time.LocalDateTime.now().format(java.time.format.DateTimeFormatter.ofPattern("MMdd-HHmmss")))
 8  
 9  heart("http://localhost:8392/") {
10      var issue = 0L
11      var pull = 0L
12      reason("open the repository $owner/$repo") {
13          reason("open an issue titled \"Crash when a bed has no name (reasoned)\", saying it was opened by a HEART script") {
14              issue = state["number"] as Long
15          }
16      }
17      reason("open the branch main of $owner/$repo") {
18          reason("start a new branch from here, named fix-blank-names-reasoned-$stamp") {
19              reason("commit a file named fix-reasoned-$stamp.md, saying \"Bed names may not be blank.\", with the message \"Refuse a bed with no name\"")
20              reason("open a pull request into main titled \"Refuse a bed with no name (reasoned)\", saying it relates to #$issue") {
21                  pull = state["number"] as Long
22                  // GitHub works out whether it can merge a new pull request a moment after it opens.
23                  until(tries = 20) { offers("github:merge") }
24                  reason("merge it, squashing its commits")
25                  check("merged" eq true)
26              }
27          }
28      }
29      reason("open issue $issue in $owner/$repo") {
30          // The comment is a new resource: visit it, then come back to the issue to close it.
31          reason("comment on it: Fixed in 1.2 by #$pull.") {
32              check("body" eq "Fixed in 1.2 by #$pull.")
33          }
34          reason("close it, since the fix is done")
35          check("state" eq "closed", "state_reason" eq "completed")
36      }
37  }
