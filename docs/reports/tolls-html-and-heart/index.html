Tolls, Live: one E-ZPass-style account as HTML and as HEART JSON

A new toll account, from opening to closing, walked against the running tolls server, each step shown as the resource a person sees in a browser and as the HEART JSON a client reads.

15 / 15steps answered as expected, 3 refused on purpose (422 under the $25 opening, 412 stale, 422 a lost tag)
1 resource/accounts/2: the holder, the balance, the tags, and the statement of payments and trips
2 dialectsthe same resource as HTML (text/html) and as HEART JSON (application/hal+json)
How to read it
  • Every act goes through a form the account's last answer offered, sent with If-Match, the version just read.
  • What is offered depends on the account's phase: new offers only add funds; open (and low, under $10) offers every act; suspended, below $0, offers only add funds and dispute; closed offers nothing.
  • In the HTML, offered acts are bright buttons that open a dialog; acts not offered are grey and say why when pressed.
  • The same server answers both dialects: no controller code per dialect, one declaration of the resource.

Next: who may do what
  • Here one credential may do every act the account's phase offers. Next, the same account read by different people offers each only their own acts.
  • The holder: add funds, add a tag, report a tag lost, dispute, close. A plaza: charge a trip, and nothing else. An agent: refund without a dispute. An auditor: read everything, act on nothing.
  • No client keeps a table of permissions: each reads what it is offered, as it reads what the phase allows now.
  • Built like basketball and baseball: domains/tolls, one declaration, no controllers.
