An 8U coach-pitch baseball game played against the running baseball server, each step shown as the resource a person sees in a browser and as the HEART JSON a client reads.

1 resource/games/1: the inning and half, outs, pitches, bases, the line score, and each player's hits and runs
2 dialectsthe same resource as HTML (text/html) and as HEART JSON (application/hal+json)
How to read it
  • Every act goes through a form the game's last answer offered, sent with If-Match, the version just read.
  • What is offered depends on the game's phase: scheduled offers only play ball; a half in play offers pitch, hit, runner out and end game; after the third out only the next half (or the end) is offered.
  • In the HTML, offered acts are bright buttons that open a dialog; acts not offered are grey and say why when pressed.
  • The same server answers both dialects: no controller code per dialect, one declaration of the resource.
