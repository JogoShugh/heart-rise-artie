Merge Watch, Junction by Junction

The GitHub gateway (heart-gateway with its GitHub connector, in front of heart-sims' small GitHub), walked through the merge watch's junctions. At each one, the same address two ways: HAL Explorer 1.2.3 asking for application/prs.hal-forms+json, HEART's L0 HAL-FORMS with its _templates; and a browser asking for text/html, HEART's page for people. The acts between junctions were sent by each template's own target and method, with the ETag just read.

What this shows

  • The offers follow the state. Pull request 482 offers merge and close while it is open and mergeable; once merged, only comment, label and edit are left. The watch's issue offers close until it is closed, then reopen.
  • Both renderings carry the same acts. Each template HAL Explorer lists is a button on the HTML page, from the same declaration.
  • The bookmark has no HAL-FORMS templates. Its ten searches and lookups are GETs with templated targets (/repos/{owner}/{repo}/pulls{?labels}), which a HAL-FORMS template can't express, so HEART leaves them out of HAL-FORMS. The HTML page offers all ten, and HAL Schema Forms carries them as _forms. A HAL-FORMS client has to be handed a deeper address to start from.
  • A list has nothing to act on. The labelled pull requests are links (item), no templates.

How it was made

  • Gateway: java -cp 'heart/heart-sims/build/sims/lib/*' com.artie.heart.sims.MainKt 8098 github.test, reset first (POST /_sim/reset): repository acme/web, pull request 482 by ada.
  • HAL Explorer 1.2.3: the webjar org.webjars:hal-explorer:1.2.3 from Maven Central (SHA-1 bb865006448dd6bb27866e9e3b9cf340a21f274c, checked), served at /explorer/ by explorer-proxy.mjs on the gateway's own origin, so it reads the gateway with no CORS; the proxy adds the sim's test credential for the browser, which can't send one.
  • The walk and the screenshots: merge-junctions.sh, headless Chrome. Each HAL-FORMS answer is kept as captured (N-name.hal-forms.json).
