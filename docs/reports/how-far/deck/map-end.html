The goal, in words (release.goal.md)
Release a pull request to Dev once it can be merged and its build passes its smoke test.

- Open pull request {pull} of {owner}/{repo} `as pr`
- At {watcher}, ask to be told when {pr} offers scm:merge `as watch`
- Once {watch} is answered, at {pr}, merge it by squashing `as merged`
- At {jenkins}, build commit {merged.merge_commit_sha}, asking to be told how it goes `as build`
- Once {build} is answered, follow its in-reply-to link to the build `as built`
  - Run the smoke script it links as ci:smoke-test, on the deployment it links as ci:deployment, with book = {book}, author = {author}, renewable = {renewable}, problem = {problem}, comment = {comment} `as smoke`
- If {smoke.passed}, at {dev}, open environment {environment} and promote commit {merged.merge_commit_sha}, citing {smoke.passing} of {smoke.of} scenarios passed `as promotion`
  Otherwise, at {pr}, act scm:comment with body = "Not promoted to Dev: smoke scenarios {smoke.failed} failed."

The kept script (release.heart.yaml)
steps:
  - act: scm:pulls-get
    fields:
      owner: ${owner}
      repo: ${repo}
      pull_number: ${pull}
    intent: Open pull request ${pull} of ${owner}/${repo}
    then:
      - keep-as: pr
  - enter: ${watcher}
    steps:
      - ask: watcher:watch
        fields:
          resource: ${pr.@self}
          offers: scm:merge
        reply: watch
  - once-answered:
      reply: watch
      steps:
        - enter: ${pr.@self}
          steps:
            - act: scm:merge
              fields:
                method: squash
              intent: merge it by squashing
              then:
                - check:
                    - field: state
                      is: closed
                    - field: merged
                      is: true
                    - field: mergeable_state
                      is: unknown
                - keep-as: merged
  - enter: ${jenkins}
    steps:
      - ask: ci:build
        fields:
          commit: ${merged.merge_commit_sha}
        reply: build
  - once-answered:
      reply: build
      steps:
        - follow: hr:in-reply-to
          intent: follow its in-reply-to link to the build
          then:
            - run-script: ci:smoke-test
              on-link: ci:deployment
              inputs:
                book: ${book}
                author: ${author}
                renewable: ${renewable}
                problem: ${problem}
                comment: ${comment}
              as: smoke
  - given:
      - at: smoke
        field: passed
        is: true
    then:
      - enter: ${dev}
        steps:
          - act: env:get-environment
            fields:
              id: ${environment}
            inferred: get environment ${environment}
            from-intent: open environment ${environment} and promote commit {merged.merge_commit_sha}, citing {smoke.passing} of {smoke.of} scenarios passed
            then:
              - act: env:promote
                fields:
                  commit: ${merged.merge_commit_sha}
                  smoke: # review: the reasoner chose it, asked "promote commit 30a0fa96e3eed2ae20b2b5fa7613a115d56312a3, citing 5 of 5 scenarios passed"
                    passed: ${smoke.passing}
                    of: ${smoke.of}
                intent: open environment ${environment} and promote commit {merged.merge_commit_sha}, citing {smoke.passing} of {smoke.of} scenarios passed
                then:
                  - check:
                      - field: commit
                        is: ${merged.merge_commit_sha}
    otherwise:
      - at: ${pr.@self}
        steps:
          - act: scm:comment
            fields:
              body: "Not promoted to Dev: smoke scenarios ${smoke.failed} failed."

scm: one set of typed relations, two forges

GitLab
scm:merge on GitLab: the gateway's connector
merge:
  operation: pulls/merge
  title: Merge
  description: Merge the pull request into its target branch.
  fields: [merge_commit_message]
  # scm's method, as GitHub's merge takes it; GitLab squashes or not, and merges with a merge commit either way.
  inputs:
    method:
      type: string
      enum: [merge, squash]
      title: Merge method
      description: The merge method to use.
  values:
    method:
      merge: { squash: false }
      squash: { squash: true }
  # GitLab merges only if the source branch's head is still at this sha: the head the client's view had.
  bind: { sha: /sha }
  # GitLab's 409: the head moved, so the client's view is stale. Its 405: it can't merge now.
  stale: 409
  refused: 405

scm:merge on GitHub: the gateway's connector
merge:
  operation: pulls/merge
  title: Merge
  description: Merge the pull request into its base branch.
  fields: [commit_title, commit_message]
  # scm's method, as GitHub's merge_method takes it.
  inputs:
    method:
      type: string
      enum: [merge, squash, rebase]
      title: Merge method
      description: The merge method to use.
  values:
    method:
      merge: { merge_method: merge }
      squash: { merge_method: squash }
      rebase: { merge_method: rebase }
  # GitHub merges only if the head is still at this sha: the head the client's view had.
  bind: { sha: /head/sha }
