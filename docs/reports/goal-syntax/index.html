Goals in Five Words

Goals in five words: On, Once, Whenever, Until, Otherwise

How a goal is written for ARTIE: in words a person would write to a colleague, that work alongside others and can keep watching. Four goals in it, every element decided, and what watching asks. Reviewed 2026-10-23.

Five words

Onthe resource the bullets under it act on, once, now
Oncewait for one offer, then act, one time
Wheneverrepeat the bullets under it on each matching change
Untilwhen a watch ends
Otherwisethe step's other outcome, as a sentence of its own

Anything that needs more than these is written in the generated Kotlin, not in the goal.

Four goals in them

The first draft, rewritten with Otherwise and Give up. goals/triage.goal.md

Goal · starts at http://localhost:8392/

Triage and fix the blank-bed-name crash, start to finish. The crash gets an issue, labelled and assigned, with a sub-issue for its test; a second report of the same crash is closed as a duplicate of it. The fix and its test go on a branch of their own, into one pull request, which is merged. Then every issue is closed the right way, and the crash's conversation is locked.

Working alongside others

Other people work in this repository while you do. What they decide stands.

  • Don't undo or write over anything someone else changed since you looked. Look again, and work from what's there now.
  • When a step no longer makes sense because of what someone did, leave it, and say why in the run's notes.
  • Nothing you write may claim something that isn't so: "fixed" only once the fix is merged.

The work

  • In {owner}/{repo}
    • Open an issue titled "Crash when a bed has no name ({stamp})", saying a bed with a blank name crashes the garden as issue
      • Label it {label}
      • Assign it to {owner}
    • Open an issue titled "Test blank bed names ({stamp})", saying it is part of #{issue.number} as test
    • Open an issue titled "Garden crashes on an empty bed name ({stamp})", saying it was seen on the demo garden as dupe
    • From the main branch, start a new branch named fix-blank-names-{stamp}
      • Commit a file named fix-{stamp}.md saying "Bed names may not be blank." with the message "Refuse a bed with no name"
      • Commit a file named test-{stamp}.md saying "A bed with a blank name is refused." with the message "Test that a blank bed name is refused"
      • Open a pull request into main titled "Refuse a bed with no name ({stamp})", saying it fixes #{issue.number} as pr
        • Add to its description that it is tested by #{test.number}
        • Once it can be merged, merge it by squashing, titled "Refuse a bed with no name (#{pr.number})".
          Otherwise, say why it wasn't merged.
          Or give up after 10 minutes.
  • On {issue}
    • Add the test issue as a sub-issue
    • Say it's fixed in #{pr.number} and tested in #{test.number}.
      Otherwise, say it waits on #{pr.number}.
    • Lock its conversation as resolved
  • On {test}
    • Say the test went in with #{pr.number}, and close it as completed
  • On {dupe}
    • Close it as a duplicate of #{issue.number}, and say it's the same crash

Done when

  • The crash issue is closed and the pull request is merged; or the pull request was held back, and the crash issue says it waits on it
  • Nothing anyone else decided was undone

  • Until {release} is tagged

Chips are the run's values; tags such as as issue name what a step made; a keyword opens a step; italic lines are a step's other outcome.

Every element, decided

  1. Headertodaykeep

    --- start: … inputs: … ---

    The entry address and the run's values, each with a question or a default.

  2. Manners settingnewadd

    manners: alongside-others

    Names the run-wide policy exactly, beside the sentences that say it to a person.

  3. Brieftodaykeep

    The first paragraph

    The task in words. The reasoner reads it; no rule is taken from it.

  4. Manners: don't overwriteproposedkeep

    Don't undo or write over anything someone else changed since you looked.

    On a 412, read again and decide again; never send again over a member someone else changed.

    Recognised as a fixed phrase, not interpreted.

  5. Manners: leave and say whyproposedkeep

    When a step no longer makes sense because of what someone did, leave it, and say why.

    Skip an act that isn't offered, and note the server's reason from hr:unavailable.

    Recognised as a fixed phrase.

  6. Manners: no false claimsproposedkeep

    Nothing you write may claim something that isn't so.

    Text that depends on an outcome is sent only once that outcome happened.

    Recognised as a fixed phrase.

  7. Manners: don't say it againnewadd

    Don't say again what has already been said.

    Before writing, read what is there; a remark already made, by this run or an earlier one, isn't made again.

    Learned from the Dependabot simulation: a restarted watch commented on three pull requests a second time.

  8. Steptodaykeep

    Open an issue titled "…", saying …

    One act, as a plain sentence.

  9. Scopetodaykeep

    In {owner}/{repo} · On {issue}

    The resource the bullets under it act on, once, now.

    "On" is a scope only. It never means an event; that word is "Whenever".

  10. Nestingtodaykeep

    An indented bullet

    Done on what its parent step made or reached; then back up.

  11. Valuetodaykeep

    {owner} · {issue.number}

    An input, or a member of what an earlier step made.

  12. Nametodaykeep

    as issue

    Names what a step made, so later steps can say {issue}.

    Step numbers stay dropped.

  13. Quoted texttodaykeep

    "Refuse a bed with no name"

    Sent exactly as written.

  14. Onceproposedkeep

    Once it can be merged, merge it by squashing.

    Wait for one offer, then act, one time.

    The phrase must map to exactly one offer, and every wait must be able to end (Give up).

  15. Add toproposedkeep

    Add to its description that it is tested by

    Append; never replace.

    GitHub refuses If-Match on writes, so append is the only safe edit of shared text.

  16. "; or, …"proposeddrop

    …; or, while that's still unmerged, that it waits on

    A second outcome, carried by a semicolon and a comma.

    Too fragile to parse. Replaced by Otherwise.

  17. "Held back as …"proposeddrop

    Held back as a draft, it stays unmerged.

    A second outcome, stated as a fact.

    Reads as a fact, so a parser can't tell an expectation from a step. Replaced by Otherwise.

  18. Otherwisenewadd

    Say it's fixed in #{pr.number}. Otherwise, say it waits on #{pr.number}.

    The step's other outcome, as a sentence of its own under the step.

  19. Give upnewadd

    Or give up after 10 minutes.

    Ends a wait. A wait also ends early, with the server's reason, when hr:unavailable says the offer won't come.

    The M4 lesson: artie-bare sent the merge 30 times against a draft.

  20. Whenevernewadd

    Whenever a pull request from dependabot opens as pr

    Repeat the bullets under it on each matching change, once per match.

    Fan-out at the top level; behaviour per resource when nested.

  21. Ifnewopen

    If it's labelled {hold}, leave it, and say so once.

    A condition on what the step holds now, read again each time the step runs.

    Not one of the five words. Either a sixth word, or the manners' "leave it" said for one case; to decide.

  22. Untilnewadd

    Until {owner} closes the issue "Auto-merge watch"

    When a watch ends.

  23. Done whenproposedkeep

    The crash issue is closed and the pull request is merged

    The final checks, written as outcomes.

  24. Done when: others keptproposedkeep

    Nothing anyone else decided was undone

    What others decided, compared with what the run left.

    Needs the resource's history to check (GitHub's timeline; generically a history link relation).

Watching for a long time

  • Events are hints. Read the resource as it is now, act only on what is offered, with its validator.
  • Polling, SSE and websockets all come down to "this resource may have changed; read it again".
  • Polling uses If-None-Match; on GitHub a 304 doesn't count against the rate limit.
  • The run trace is the watcher's journal; it resumes from it after a restart.
  • No model call per event. The goal is reasoned once; the generated script handles every event.
  • One handler at a time per resource, so two events for one pull request don't race.

fun Any?.map(): Map<String, Any?> = (this as? Map<*, *>).orEmpty().entries.associate { it.key.toString() to it.value }
fun Any?.list(): List<Any?> = (this as? List<*>).orEmpty()
fun Map<String, Any?>.text(key: String) = this[key]?.toString().orEmpty()
fun esc(s: String) = s.replace("&", "&amp;").replace("<", "&lt;").replace(">", "&gt;").replace("\"", "&quot;")

/** The words that open a step or a line under it, each shown as a keyword. */
val keywords = Regex("""^(In|On|Once|Whenever|Until|If|Otherwise,|Or give up)(?!\w)""")

/** A line of a goal as read: values as chips, names as tags, its opening keyword marked. */
fun inline(line: String): String = esc(line)
    .replace(Regex("""`as (\w+)`""")) { """<span class="as">as ${it.groupValues[1]}</span>""" }
    .replace(Regex("""\{([\w.]+)\}""")) { """<span class="val">{${it.groupValues[1]}}</span>""" }
    .replace(keywords) { """<span class="kw">${it.value}</span>""" }

/** One bullet: its depth, its first line, and the lines under it that aren't bullets ("Otherwise, …"). */
class Item(val depth: Int, val lines: MutableList<String>)

fun bullets(lines: List<String>): List<Item> {
    val items = mutableListOf<Item>()
    lines.filter { it.isNotBlank() }.forEach { line ->
        val indent = line.length - line.trimStart().length
        val text = line.trim()
        if (text.startsWith("- ")) items += Item(indent / 2, mutableListOf(text.removePrefix("- ")))
        else items.lastOrNull()?.lines?.add(text)
    }
    return items
}

fun renderItems(items: List<Item>, depth: Int = 0): String {
    val sb = StringBuilder("<ul>")
    var i = 0
    while (i < items.size) {
        val item = items[i]
        var j = i + 1
        while (j < items.size && items[j].depth > depth) j++
        val rest = item.lines.drop(1).joinToString("") { """<div class="alt">${inline(it)}</div>""" }
        sb.append("<li><div>${inline(item.lines.first())}</div>$rest")
        if (j > i + 1) sb.append(renderItems(items.subList(i + 1, j), depth + 1))
        sb.append("</li>")
        i = j
    }
    return sb.append("</ul>").toString()
}

/** A goal as read: header values, the brief, and each section, the manners and the checks set apart. */
fun renderGoal(text: String): String {
    val parts = text.split(Regex("""(?m)^---\s*$"""), limit = 3)
    val head = Yaml().load<Any?>(parts[1]).map()
    val body = parts[2].lines()
    val inputs = head["inputs"].map().entries.joinToString("") { (name, spec) ->
        val s = spec.map()
        val default = s["default"].let { d -> d.map()["now"]?.let { "now, as $it" } ?: d?.toString() ?: "–" }
        """<tr><td><span class="val">{$name}</span></td><td>${esc(s.text("question"))}</td><td>${esc(default)}</td></tr>"""
    }
    val sections = mutableListOf("" to mutableListOf<String>())
    body.forEach { line ->
        if (line.startsWith("## ")) sections += line.removePrefix("## ").trim() to mutableListOf()
        else sections.last().second += line
    }
    val brief = sections.first().second.joinToString(" ") { it.trim() }.trim()
    val rest = sections.drop(1).joinToString("") { (title, lines) ->
        val paragraphs = lines.takeWhile { !it.trimStart().startsWith("- ") }.joinToString(" ") { it.trim() }.trim()
        val list = renderItems(bullets(lines.dropWhile { !it.trimStart().startsWith("- ") }))
        val cls = when (title) { "Working alongside others" -> "manners"; "Done when" -> "done"; else -> "work" }
        """<h3>${esc(title)}</h3><div class="$cls">${if (paragraphs.isEmpty()) "" else "<p>${inline(paragraphs)}</p>"}$list</div>"""
    }
    return """<p class="kicker">Goal · starts at ${esc(head.text("start"))}""" +
        "</p>" + (if (head["manners"] != null) """<p class="sub">manners: <span class="val">${esc(head.text("manners"))}</span></p>""" else "") +
        """<div class="scroll inputs"><table><thead><tr><th>Asks for</th><th>Question</th><th>Unless given</th></tr></thead>""" +
        """<tbody>$inputs</tbody></table></div><p class="brief">${inline(brief)}</p>$rest"""
}

}

// The goal tabs show one goal; the view tabs switch every goal between as read and its source.
(function () {
  function group(id, pick) {
    var buttons = document.querySelectorAll('#' + id + ' button');
    buttons.forEach(function (b) {
      b.addEventListener('click', function () {
        buttons.forEach(function (o) { o.setAttribute('aria-pressed', String(o === b)); });
        pick(b);
      });
    });
  }
  group('goal-tabs', function (b) {
    document.querySelectorAll('.goal').forEach(function (g) { g.hidden = g.dataset.goal !== b.dataset.goal; });
  });
  group('view-tabs', function (b) { document.getElementById('goals').dataset.view = b.dataset.view; });
})();
"""
