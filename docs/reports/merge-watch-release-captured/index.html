How it goes

  • The goal is plain text (release.goal.md): open the pull request, ask the watcher to be told when it can be merged, merge it, ask Jenkins to build, run the smoke script the build links, promote or comment.
  • One walk with Claude. The model chose each act from what each answer offered. The steps the grammar covers ran with no model: At a party, Once a reply, Run the script, If.
  • The walk kept as a script. artie generate wrote every value as the input or the name it came from: the pull request to watch is ${pr.@self}, the build's commit ${merged.merge_commit_sha}, Dev's environment ${environment}, the smoke score it cites ${smoke.passing} of ${smoke.of}.
  • Five releases, five sets of inputs. A different pull request and policy change each, and a different book, problem and comment for the smoke test. Same script every time; the real Jenkins builds each.

The goal, and the script kept from it

release.goal.md, the plain-text goal
---
start: "{github}"
inputs:
  pull:      { question: "Which pull request?" }
  owner:     { default: acme }
  repo:      { default: web }
  github:    { default: "http://192.168.1.18:8098/" }
  watcher:   { default: "http://192.168.1.18:8099/" }
  jenkins:   { default: "http://192.168.1.18:8170/" }
  dev:       { default: "http://192.168.1.18:8190/" }
  environment: { default: "1" }
  book:      { default: "The Hobbit" }
  author:    { default: "J. R. R. Tolkien" }
  renewable: { default: "Matilda" }
  problem:   { default: "missing-pages" }
  comment:   { default: "Pages 12 to 14." }
---

Release a pull request to Dev once it can be merged and its build passes its smoke test.

- Open pull request {pull} of {owner}/{repo} `as pr`
- At {watcher}, ask to be told when {pr} offers github:merge `as watch`
- Once {watch} is answered, at {pr}, merge it by squashing `as merged`
- At {jenkins}, build commit {merged.merge_commit_sha}, asking to be told how it goes `as build`
- Once {build} is answered, follow its in-reply-to link to the build `as built`
  - Run the smoke script it links as ci:smoke-test, on the deployment it links as ci:deployment, with book = {book}, author = {author}, renewable = {renewable}, problem = {problem}, comment = {comment} `as smoke`
- If {smoke.passed}, at {dev}, open environment {environment} and promote commit {merged.merge_commit_sha}, citing {smoke.passing} of {smoke.of} scenarios passed `as promotion`
  Otherwise, at {pr}, act github:comment with body = "Not promoted to Dev: smoke scenarios {smoke.failed} failed."
