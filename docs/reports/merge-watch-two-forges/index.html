One Script, Two Forges

The release goal walked once with Claude on GitHub and kept as a script. The same script then released five pull requests on GitHub and five merge requests on GitLab, with no model. Follows The Release, Captured Once with Claude.

1 capture, on GitHub: 20 calls claude-sonnet-5-5 · 33,876 input tokens · 3,040 output · 29,424 read from cache · 61 steps in 58 s · the capture
GitHub: 5 replays, 0 calls 56 to 61 steps, 18 to 22 s each · 4 promoted, 504 stopped by S3 as it should
GitLab: 5 replays, 0 calls same script, unchanged · 56 to 61 steps, 16 to 18 s each · 4 promoted, 504 stopped by S3 as it should

How it works

  • One set of words for both forges. The goal and the script name relations from a shared scm: profile: scm:pulls-get, scm:merge, scm:comment. Neither says GitHub or GitLab. The only difference between the runs is one input: scm, the gateway's address.
  • One gateway program, two connectors. Each forge sits behind the HEART gateway with its own connector: github-scm on 8098, gitlab on 8094. A connector is declarations only, no code.
  • Normalized on the way out. Each connector answers in scm's words. GitLab's opened reads as open, its merged as closed with merged: true, and its detailed_merge_status as mergeable_state. Where a value had to change, GitLab's own is kept under upstream. Going in, scm's method: squash becomes GitHub's merge_method: squash or GitLab's squash: true.
  • Everything else is the same parties. The watcher, the CI wrapper in front of the real Jenkins, the library preview and Dev. On GitLab, Jenkins fetches the merged commit from GitLab.

What each connector says

github-scm: the merge act

  merge:
    operation: pulls/merge
    title: Merge
    description: Merge the pull request into its base branch.
    fields: [commit_title, commit_message]
    # scm's method, as GitHub's merge_method takes it.
    inputs:
      method:
        type: string
        enum: [merge, squash, rebase]
        title: Merge method
        description: The merge method to use.
    values:
      method:
        merge: { merge_method: merge }
        squash: { merge_method: squash }
        rebase: { merge_method: rebase }
    # GitHub merges only if the head is still at this sha: the head the client's view had.
    bind: { sha: /head/sha }
    # GitHub's 409: the head moved, so the client's view is stale. Its 405: it can't merge now.
    stale: 409
    refused: 405

gitlab: the merge act

  merge:
    operation: pulls/merge
    title: Merge
    description: Merge the pull request into its target branch.
    fields: [merge_commit_message]
    # scm's method, as GitHub's merge takes it; GitLab squashes or not, and merges with a merge commit either way.
    inputs:
      method:
        type: string
        enum: [merge, squash]
        title: Merge method
        description: The merge method to use.
    values:
      method:
        merge: { squash: false }
        squash: { squash: true }
    # GitLab merges only if the source branch's head is still at this sha: the head the client's view had.
    bind: { sha: /sha }
    # GitLab's 409: the head moved, so the client's view is stale. Its 405: it can't merge now.
    stale: 409
    refused: 405
gitlab: normal, GitLab's state in scm's words
normal:
  state:
    from: /state
    values: { opened: open, closed: closed, locked: closed, merged: closed }
  merged:
    from: /state
    values: { opened: false, closed: false, locked: false, merged: true }
  # Whether it can be merged now, in the words GitHub's pull requests use: unknown while GitLab works it out, and
  # once it isn't open.
  mergeable_state:
    from: /detailed_merge_status
    values:
      mergeable: clean
      not_open: unknown
      checking: unknown
      unchecked: unknown
      preparing: unknown
      conflict: dirty
      need_rebase: behind
      draft_status: draft
      ci_must_pass: blocked
      ci_still_running: blocked
      not_approved: blocked
      discussions_not_resolved: blocked
      blocked_status: blocked
      jira_association_missing: blocked
      external_status_checks: blocked
      merge_request_blocked: blocked

The goal, and the script kept from it

release.goal.md, the plain-text goal
---
start: "{scm}"
inputs:
  pull:      { question: "Which pull request?" }
  owner:     { default: acme }
  repo:      { default: web }
  scm:       { default: "http://192.168.1.18:8098/" }
  watcher:   { default: "http://192.168.1.18:8099/" }
  jenkins:   { default: "http://192.168.1.18:8170/" }
  dev:       { default: "http://192.168.1.18:8190/" }
  environment: { default: "1" }
  book:      { default: "The Hobbit" }
  author:    { default: "J. R. R. Tolkien" }
  renewable: { default: "Matilda" }
  problem:   { default: "missing-pages" }
  comment:   { default: "Pages 12 to 14." }
---

Release a pull request to Dev once it can be merged and its build passes its smoke test.

- Open pull request {pull} of {owner}/{repo} `as pr`
- At {watcher}, ask to be told when {pr} offers scm:merge `as watch`
- Once {watch} is answered, at {pr}, merge it by squashing `as merged`
- At {jenkins}, build commit {merged.merge_commit_sha}, asking to be told how it goes `as build`
- Once {build} is answered, follow its in-reply-to link to the build `as built`
  - Run the smoke script it links as ci:smoke-test, on the deployment it links as ci:deployment, with book = {book}, author = {author}, renewable = {renewable}, problem = {problem}, comment = {comment} `as smoke`
- If {smoke.passed}, at {dev}, open environment {environment} and promote commit {merged.merge_commit_sha}, citing {smoke.passing} of {smoke.of} scenarios passed `as promotion`
  Otherwise, at {pr}, act scm:comment with body = "Not promoted to Dev: smoke scenarios {smoke.failed} failed."

steps:
  - act: scm:pulls-get
    fields:
      owner: ${owner}
      repo: ${repo}
      pull_number: ${pull}
    intent: Open pull request ${pull} of ${owner}/${repo}
    then:
      - keep-as: pr
  - enter: ${watcher}
    steps:
      - ask: watcher:watch
        fields:
          resource: ${pr.@self}
          offers: scm:merge
        reply: watch
  - once-answered:
      reply: watch
      steps:
        - enter: ${pr.@self}
          steps:
            - act: scm:merge
              fields:
                method: squash
              intent: merge it by squashing
              then:
                - check:
                    - field: mergeable_state
                      is: unknown
                    - field: merged
                      is: true
                    - field: state
                      is: closed
                - keep-as: merged
  - enter: ${jenkins}
    steps:
      - ask: ci:build
        fields:
          commit: ${merged.merge_commit_sha}
        reply: build
  - once-answered:
      reply: build
      steps:
        - follow: hr:in-reply-to
          intent: follow its in-reply-to link to the build
          then:
            - run-script: ci:smoke-test
              on-link: ci:deployment
              inputs:
                book: ${book}
                author: ${author}
                renewable: ${renewable}
                problem: ${problem}
                comment: ${comment}
              as: smoke
  - given:
      - at: smoke
        field: passed
        is: true
    then:
      - enter: ${dev}
        steps:
          - act: env:get-environment
            fields:
              id: ${environment}
            inferred: get environment ${environment}
            from-intent: open environment ${environment} and promote commit {merged.merge_commit_sha}, citing {smoke.passing} of {smoke.of} scenarios passed
            then:
              - act: env:promote
                fields:
                  commit: ${merged.merge_commit_sha}
                  smoke:
                    passed: ${smoke.passing}
                    of: ${smoke.of}
                intent: open environment ${environment} and promote commit {merged.merge_commit_sha}, citing {smoke.passing} of {smoke.of} scenarios passed
                then:
                  - check:
                      - field: commit
                        is: ${merged.merge_commit_sha}
    otherwise:
      - at: ${pr.@self}
        steps:
          - act: scm:comment
            fields:
              body: "Not promoted to Dev: smoke scenarios ${smoke.failed} failed."
