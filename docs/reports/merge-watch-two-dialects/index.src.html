How it works

  • One set of words in both dialects. A HAL-FORMS template is named by its relation, as a HAL Schema Forms form is: scm:merge, watcher:watch, ci:build, library:renew, env:promote. The script kept from the HAL-FORMS walk names the same relations as the other.
  • Lookups as link templates. A HAL-FORMS target can't carry variables, so the forge offers scm:pulls-get as a link template, /repos/{owner}/{repo}/pulls/{pull_number}, and ARTIE fills it as a GET form.
  • Choices filled in. Where a property's choices sit inside another resource (the library's problem kinds), a HAL-FORMS template carries them inline; HAL-FORMS has no way to point inside a document.
  • The same parties, the same smoke script. Watcher, CI wrapper over the real Jenkins, the library preview and Dev answer in whichever dialect ARTIE asks; the smoke test the build links runs unchanged in either.
  • What HAL-FORMS can't pin. Its templates carry no integrity hash, so the HAL-FORMS script pins no form, only two links: a replay can't tell a changed form the way a HAL Schema Forms replay can.
