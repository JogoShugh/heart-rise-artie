Decisions, and why

6 decisions a reviewer should check
  • One resource, the account. Trips, tags and payments are its statement, not resources of their own: the account's state decides every act, which is what HEART shows.
  • Money in whole cents. No floating point anywhere; dollars only on the wire, as text.
  • A trip records the fare it was charged. A later change to the fare table never rewrites a past trip.
  • The phase is computed, not stored. Baseball, an hour earlier, broke when a computed property was written into the state's snapshot; the account's phase is a function for that reason.
  • Low balance offers the same acts as active. It is a warning, not a restriction; only below $0 do the tags stop paying.
  • Roles left out on purpose. One credential may do every act its phase offers. Roles are the next session (see Resume here).

How a teammate picks it up

  • The session writes this page and a HANDOFF.md to docs/sessions/<date>-<slug>/ and commits them with the work. A teammate gets both with git pull, in their own clone, under their own Claude account: nothing is shared but the repository.
  • HANDOFF.md is the same content, short, for a model to read: the ask in the author's words, the state, the decisions, the open items, the next step.
  • No transcript, no tokens, no secrets: built from git, the gate's event log and the session's own notes, and scanned for credentials before it is written.
  • On GitHub Pages too, once pushed, so a reviewer needs only a link.
