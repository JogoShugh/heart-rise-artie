Give the answer its controls

If the API answered like the page

Your client asks for a loan and gets, in the same answer, what it can do with it now and why the rest isn't there. It chooses among offers instead of reading a manual, and anything stale or not offered is refused with a reason.

The same office, an hour later. Sam has the marker.

  • Information: stays as it is, the same JSON members.
  • Controls move in: links, forms by state, the reason for each absent one, a version tag, and one shared set per state.
  • On standards: HAL, HAL-FORMS and JSON Schema, ETag and If-Match, content-addressed sets.
Priya

What would it take to give the API what Ana's page has?

Sam

Six things. Her page already does every one.

Before: a loan as JSON over HTTP 
GET /loans/3310   Accept: application/json

{ "id": 3310, "title": "The Hobbit", "author": "J. R. R. Tolkien",
  "due": "2026-11-12", "renewals": 0, "standing": "hold waiting" }

Data only. What can be done is in the OpenAPI document, for every loan alike.

  1. The answer links itself and names its vocabulary.“So library:renew means the same thing to every client.”
    On the wire 
    + "_links": {
+   "self": { "href": "/loans/3310" },
+   "curies": [ { "name": "library", "href": "/profiles/library#{rel}", "templated": true } ]
+ }
  2. The acts arrive as forms.“Where to send, which method, what to put in: the OpenAPI operation, moved into the loan.”
    On the wire (Matilda) 
    + "_forms": {
+   "library:renew": {
+     "title": "Renew",
+     "_links": { "target": { "href": "/loans/3311/actions/renew" } },
+     "method": "POST",
+     "contentType": "application/json",
+     "schema": { "type": "object", "properties": {} }
+   },
+   "library:return": { … }
+ }
  3. The forms follow the state.“Matilda gets renew and return. The Hobbit gets return only.”
    On the wire (The Hobbit) 
      "standing": "hold waiting",
  "_forms": {
-   "library:renew": { … },
    "library:return": { … }
  }
  4. What's absent says why.“The grey button with its reason, as data.”
    On the wire 
    + "hr:unavailable": { "href": "/unavailable/61bc1cd6003e61f0" }

GET /unavailable/61bc1cd6003e61f0
{ "unavailable": [ { "rel": "/profiles/library#renew", "title": "Renew",
    "reason": "A hold is waiting for this book, so it can't be renewed." } ] }
  5. A version tag guards the act.“Send back the tag you read. Stale is refused, 412, not a surprise.”
    On the wire 
    ETag: "seq-1.hsf.L0.d96396fb7e046607"

POST /loans/3311/actions/renew   If-Match: "seq-0.stale"
412 Precondition Failed   The act is stale: the state has changed
  6. One form set per state, shared.“Every loan with a hold waiting links the same set: fetched once, checked by its hash, cached.”
    On the wire (L2) 
    - "_forms": { … },
+ "hr:forms": { "href": "/affordance-sets/31a5b6105822d925",
+               "integrity": "sha256-MaW2EFgi2SXHXtDeNNqfRqaPpMhuPfrUB/RV+oPsfQ8=" }
