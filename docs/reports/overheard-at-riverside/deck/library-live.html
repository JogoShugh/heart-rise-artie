The library, live, both ways

One heart-ts client against Riverside's running library service, recorded.

  1. Asked for plain JSON.The Hobbit comes back as data: its title, due 2026-11-12, standing “hold waiting”. No forms, no links.
  2. It tries to renew.“library:renew is not offered now; nothing was sent.” Plain JSON offers no acts.
  3. The same code, asking for HEART.The Hobbit offers report a problem and return, and not renew.
  4. And Matildaoffers renew, report a problem and return.
  5. A plain JSON parser reads the HEART answer.Title, due date and standing are all there; _links and _forms are extra members it ignores. The upgrade breaks no old client.
  6. A browser asks for text/html.It gets Matilda's page, from the same service.
How the service decides what to send
  • Accept: application/json: plain JSON, the state with no controls.
  • Accept: application/hal+json: HAL Schema Forms.
  • Accept: text/html: the page, for people.
  • No Accept, or */*: one default, HAL-FORMS at L0. HTTP reads a missing Accept as “anything”, so both get the same answer.
  • A client upgrades when it asks for HEART; a service upgrades when it names its profile. Both are optional.
