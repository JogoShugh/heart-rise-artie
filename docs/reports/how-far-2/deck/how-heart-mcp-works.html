heart-mcp · six tools that never change
heart_lookgo to a bookmark, or read this resource again
heart_acttake one offered act, by name, with fields
heart_followfollow a link, by rel and title
heart_describethe service’s fuller description of an act
heart_explainwhy an act isn’t offered now; nothing is sent
heart_backback one resource, read again
checks the choice: is the act offered? do the fields fit its schema? If not, nothing is sent.

ARTIE, inside

builds every request: address, method, If-Match, credential, L2 forms with integrity checked

→ any HEART service, or the gateway in front of GitHub

Every answer holds

state · the resource’s fields
acts · offered now: name, title, description, schema
links · rel and title
outcome · acted · rejected-before-sending · stale · not-offered · invalid-input · rule-refused

What the model never sees

an address, a method, a header, a validator, a credential

It can’t build a request, and it can’t call an act that isn’t offered.
