Tool search: a smaller bag, still a bag

What it gives, and it’s real

Tool definitions marked defer_loading: true stay out of the model’s context until a search over their names and descriptions (regex or BM25) finds them.

49 → 74%Opus 4 on MCP evaluations with large tool libraries (Anthropic’s figures)
79.5 → 88.1%Opus 4.5, same evaluations

Claude Code uses it too. It solves context size; HEART’s L1 and L2 solve the same with caching.

What it finds is still RPC

# a tool definition, illustrative
name: merge_pull_request
description: Merge a pull request.
input_schema:
  owner, repo, pull_number,
  merge_method: [merge, squash, rebase],
  sha
defer_loading: true

A function and its parameters: the same for every pull request, in every state. Chosen by the words of the task, not the state of anything.

Finds: the right functions to call. Never says: which acts are open now, on which address, or why not. That still arrives as an error after the call.

In fairness: MCP lets a server change its tool list during a session (notifications/tools/list_changed). That list belongs to the session, not to one resource’s representation.
