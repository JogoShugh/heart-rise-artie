# SKILL.md, the opening
Instructions are advisory. A model can drift
past them. These gates are real processes with
real exit codes, so they hold even when
attention slips. This skill installs them and
explains the loop they enforce. **The skill
never replaces the hooks**: if a gate blocks
you, satisfy it; never edit it away.

# SKILL.md, the work loop
1. Write or change the .feature scenario.
   Use Scenario Outlines and data tables,
   not repeated Given/When/Then blocks.
2. Run the BDD suite (native command, or
   .claude/bdd-gates/bdd-run.sh on wrapper
   stacks). See it fail for the right
   reason: BDD_RUN FAIL.
3. Write step definitions, then production
   code. The gate now allows it.
4. Run the suite until BDD_RUN PASS. Fix
   lint findings as they appear.
5. End the turn. The Stop gate runs the
   full check.
