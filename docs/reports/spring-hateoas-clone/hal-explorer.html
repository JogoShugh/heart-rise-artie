HAL Explorer on Both

Kai Tödter's HAL Explorer 1.2.3, a browser client for HAL and HAL-FORMS, pointed at the stock Spring clone and at a HEART service at L0 (the Riverside library's loan 3310). It is the explorer Spring Data REST ships; nothing in it was changed.

Pointed atAsked forWhat HAL Explorer shows
Stock Spring clone, employee 1application/prs.hal-forms+json Two links, self and employees, and two templates, default (put) and deleteEmployee (delete), with no title, no target, no ETag, no profile: Spring's example as it ships.
HEART, loan 3310application/prs.hal-forms+json Three titled templates (Renew, Report a problem, Return), each with its target and content type; the headers carry Content-Profile, the ETag, the alternate links and Vary; report-problem's choices come by options.link.
HEART, loan 3310application/hal+json (HAL Schema Forms) No forms: HAL Explorer doesn't know HAL Schema Forms, so _forms is shown as data. HEART's own dialect needs a client that reads it, or its HTML page for people.

How it was run

  • The webjar org.webjars:hal-explorer:1.2.3 from Maven Central, SHA-1 bb865006448dd6bb27866e9e3b9cf340a21f274c checked against Maven Central's.
  • Served at /explorer/ by a small proxy on each server's own origin, so it reads the server with no CORS change (docs/reports/merge-watch-junctions/explorer-proxy.mjs).
  • Headers given in HAL Explorer's own address fragment (#hkey0=Accept&hval0=…&uri=…); the library's test card for its Basic credential. Headless Chrome, screenshots as loaded: no form opened or sent.
