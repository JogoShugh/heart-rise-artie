The Merge Watch Release

A pull request released to Dev across five parties.

  • Each party is its own HEART service at its own address:
    • GitHub, through the gateway
    • an offer watch
    • a real Jenkins, behind a wrapper
    • the preview Jenkins deploys
    • Dev
  • Every wait is a RISE reply. ARTIE makes the reply before it asks; the party it asks answers it, signed.
  • Every address after a party's entry is handed over by an answer's links.

Reason once, then run again and again with other inputs, no model

  • One inference run. ARTIE walked the smoke test's plain-text goal once, Claude (claude-sonnet-5-5) planning each move, against a preview known to be good: 23 model calls, 34,029 input tokens, 3,467 output, 44,321 read from cache. The capture.
  • Kept as a script with slots. artie generate wrote the walk as smoke.heart.yaml: every value the model used is the input or the name it came from (${book}, ${renewable}, ${before.due}, ${problem}), none left to review. The stale renewal of S4 is kept as an act as of the version read before, its refusal expected.
  • Five releases, five sets of inputs, zero model calls. Each a different pull request and policy change, and a different book, problem and comment for the smoke test, run by ARTIE in the release desk through the real Jenkins. The same kept scripts every time; only the inputs vary.

What happens in a release, in order

  1. A person asks the desk to release a pull request, giving the smoke test's inputs. The desk starts ARTIE on the kept release script with those inputs.
  2. ARTIE opens the pull request through the gateway, asks the offer watch to be told on a reply the desk keeps when it offers github:merge, and waits. The watch answers the reply, signed; the desk wakes the run.
  3. ARTIE follows the links the answer hands over to the pull request and merges it by squashing: a real commit.
  4. It asks the CI wrapper to build that commit, on another reply. Jenkins builds and deploys the preview; its notifications reach the wrapper, whose ARTIE answers the reply, signed, linking the deployment and the smoke script the build archived.
  5. ARTIE runs that smoke script, the one captured with Claude, against the deployment, with the release's inputs.
  6. Every scenario passed: it promotes the merged commit to Dev, citing the smoke run. Not all: it comments on the pull request with the scenarios that failed.

S4Renew it again as of the version read before: refused as stalerenew as-of: read, refused-as: stale
S5Report {problem} on {book}, saying {comment}: the loan shows itreport with ${problem}, ${comment}; check /reported/problem

S3 checks that renewing moves the due date at all, not that it moves three weeks: a captured date would hold on one day only, while "moved" holds on every run, and a policy of zero weeks still fails it (504).

What is ARTIE's, and what is not yet

  • ARTIE runs every release, inside the release desk, and answers every reply, inside the offer watch and the CI wrapper, each signing with its own key. No party is a scripted stand-in.
  • The smoke script was captured from one run with Claude. The release script, release.heart.yaml, is still written by hand from release.goal.md: capturing it too needs the goal grammar to say "At {party}", "asking to be told", and "Once {reply} …". That is the next step.
  • GitHub's working out whether a pull request can be merged is set through the small GitHub's control route by the script that asks for each release (variants.sh), as GitHub would on its own time.

Check that the library works as a member would use it. Each scenario starts at the library's entry.

- Search the loans for "{book}", and open {book} `as found` `scenario S1`
- Search the loans for "{book}", and open {book} `as loan` `scenario S2`
  - Verify: author is {author}
- Search the loans for "{renewable}", and open {renewable} `as before` `scenario S3`
  - Renew it
  - Verify: due is not {before.due}
- Search the loans for "{renewable}", and open {renewable} `as read` `scenario S4`
  - Renew it
  - Renew it again as of {read}: it should be refused as stale
- Search the loans for "{book}", and open {book} `as reported` `scenario S5`
  - Report {problem} on it, saying "{comment}"
  - Verify: reported.problem is {problem}

release.goal.md
---
start: http://localhost:8098/
inputs:
  owner:   { default: acme }
  repo:    { default: web }
  pull:    { question: "Which pull request?" }
  watcher: { default: http://localhost:8099/ }
  jenkins: { default: http://localhost:8170/ }
  dev:     { default: http://localhost:8190/ }
---

Release a pull request to Dev once it can be merged and its build passes its smoke test.

- In {owner}/{repo}, open pull request {pull} `as pr`
- At {watcher}, ask to be told when {pr} offers `github:merge` `as watch`
- Once {watch} says it does, follow the pull request it links, and merge it by squashing `as merged`
  Or give up after 30 minutes, and comment on {pr} why.
- At {jenkins}, build commit {merged.merge_commit_sha}, asking to be told how it goes `as build`
- Once {build} has succeeded:
  - Follow its `ci:deployment` link `as preview`
  - Run the smoke script {build} links as `ci:smoke-test`, with deployed = {preview} `as smoke`
  Or, once {build} has failed, comment on {pr} with the stage that failed, linking the log {build} links as `ci:log`.
- At {dev}, open Dev; if {smoke.passed}, promote commit {merged.merge_commit_sha}, citing {smoke} `as promotion`
  Otherwise, comment on {pr} with the scenarios that failed and why.
release.heart.yaml, written by hand from it, until its own capture
# The release, kept as a script held as data: release.goal.md, as the release desk's ARTIE runs it. Every value
# flows by name (`keep-as`, `${name.member}`); every wait is a reply the desk keeps (`ask`, `once-answered`); every
# address after a party's entry is one an answer handed over, followed by its link or read where it was kept. Each
# step goes on only from the one before it: the build is asked for once merged, the smoke run once built.
heart: 1
kind: kept
inputs:
  pull: {type: integer}
  owner: {default: acme}
  repo: {default: web}
  github: {default: "http://192.168.1.18:8098"}
  watcher: {default: "http://192.168.1.18:8099"}
  ci: {default: "http://192.168.1.18:8170"}
  dev: {default: "http://192.168.1.18:8190"}
  # What the smoke test is given on this release: the slots its captured script fills, a value each.
  book: {default: "The Hobbit"}
  author: {default: "J. R. R. Tolkien"}
  renewable: {default: "Matilda"}
  problem: {default: "missing-pages"}
  comment: {default: "Pages 12 to 14."}
start: ${github}/
steps:
  # In {owner}/{repo}, open pull request {pull} `as pr`
  - act: github:pulls-get
    fields: {owner: "${owner}", repo: "${repo}", pull_number: "${pull}"}
  - keep-as: pr
  # At {watcher}, ask to be told when {pr} offers `github:merge` `as watch`
  - enter: ${watcher}/
    steps:
      - ask: watcher:watch
        fields: {resource: "${pr.@self}", offers: "github:merge", looks: 600}
        reply: watch
      # Once {watch} says it does, follow the pull request it links, and merge it by squashing `as merged`
      - once-answered:
          reply: watch
          give-up: 30m
          steps:
            - follow: hr:in-reply-to
            - follow: about
            - act: github:merge
              fields: {merge_method: squash}
            - at: ${pr.@self}
              steps:
                - keep-as: merged
            # At {ci}, build commit {merged.merge_commit_sha}, asking to be told how it goes `as build`
            - enter: ${ci}/
              steps:
                - ask: ci:build
                  fields: {commit: "${merged.merge_commit_sha}"}
                  reply: build
                - once-answered:
                    reply: build
                    give-up: 20m
                    # Once {build} has succeeded: run the smoke script it links on the deployment it links `as smoke`
                    steps:
                      - follow: hr:in-reply-to
                      - run-script: ci:smoke-test
                        inputs:
                          deployed: "${build.result._links.ci:deployment.href}"
                          book: "${book}"
                          author: "${author}"
                          renewable: "${renewable}"
                          problem: "${problem}"
                          comment: "${comment}"
                        as: smoke
                      - note: "Smoke: ${smoke.passing} of ${smoke.of} passed. Failed: ${smoke.failed}"
                      # At {dev}, if {smoke.passed}, promote the merged commit, citing {smoke} `as promotion`
                      - given: [{at: smoke, field: passed, is: true}]
                        then:
                          - enter: ${dev}/
                            steps:
                              - act: env:get-environment
                                fields: {id: 1}
                              - act: env:promote
                                fields:
                                  commit: "${merged.merge_commit_sha}"
                                  smoke: {passed: "${smoke.passing}", of: "${smoke.of}"}
                                  _links:
                                    "env:smoke-run": {href: "http://192.168.1.18:8200/reports/merge-watch-release/"}
                              - keep-as: promotion
                              - note: "Released: promoted ${merged.merge_commit_sha} to Dev."
                        # Otherwise, comment on {pr} with the scenarios that failed.
                        otherwise:
                          - at: ${pr.@self}
                            steps:
                              - act: github:comment
                                fields: {body: "Not promoted to Dev: smoke scenarios ${smoke.failed} failed."}
                          - note: "Stopped as it should: smoke ${smoke.failed} failed, so not promoted; said why on the pull request."
                    # Or, once {build} has failed, comment on {pr} with what failed, linking the log.
                    failed:
                      - at: ${pr.@self}
                        steps:
                          - act: github:comment
                            fields: {body: "Not released: ${build.detail}. Log: ${build._links.ci:log.href}"}
          # The watch gave up: say so on {pr}.
          failed:
            - at: ${pr.@self}
              steps:
                - act: github:comment
                  fields: {body: "Not released: ${watch.detail}."}
          # Or give up after 30 minutes, and comment on {pr} why.
          otherwise:
            - at: ${pr.@self}
              steps:
                - act: github:comment
                  fields: {body: "Not released: ${why}."}
