The Merge Watch Release

A pull request released to Dev across five parties, each its own HEART service at its own address: GitHub through the gateway, an offer watch, a real Jenkins behind a wrapper, the preview it deploys, and Dev. Every wait is a RISE reply ARTIE made before asking, answered signed by the party it asked. Every address after each party's entry was handed over by an answer.

What happened, in order

  1. ARTIE reads the gateway's entry and opens the pull request.
  2. It makes its reply, then asks the offer watch to be told when the pull request offers github:merge. GitHub is still working out mergeability; the watch says it is still looking, then, once GitHub has, answers the reply, linking the pull request.
  3. ARTIE follows that link and merges by squashing: a real commit on main in git. It reads the merge commit's sha from the pull request.
  4. It makes another reply and asks the CI wrapper to build that commit. The wrapper starts the Jenkins job; Jenkins' notifications become signed answers: progress, then completed, linking the deployment, the smoke script it archived, and the log.
  5. ARTIE reads the smoke script the build links, and runs the scenarios against the deployment it links.
  6. All passed: it promotes the merged commit to Dev, citing the smoke run. Not all: it comments on the pull request with those that failed.

What is and isn't ARTIE yet

  • These runs were made by ReleaseTrace (heart-sims tests), a scripted client that plays ARTIE's part step by step, by the goal below, by links alone. It is not yet ARTIE running release.goal.md: that needs two additions to the goal grammar, At {url} (another party's entry, mid-goal) and running a script a link hands over. Those are the next step.
  • The smoke scenarios are coded in the same client, from smoke.goal.md; the build archives and links that goal. Capturing it as a kept script, walked once by ARTIE with the model, comes with the grammar.
  • ARTIE's replies are made through the release's control route (POST /_release/replies/{reply}), as ARTIE's runner will make them itself.
  • The offer watch is its own party, not part of the gateway: the gateway has no watch, and this one works for any HEART resource.
