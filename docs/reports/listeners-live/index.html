The same watch, two ways

One watch over the scratch repository, through the HEART gateway: a stand-in veracode-bot's failed scan is held for security, each alert is answered once, and each triage comment is handled slowly, 15 seconds, as a model call is. The same timeline played against it twice: once as three listeners, each on its own, once as today's single loop, every 10 seconds.

Eventthree listeners (l1)one loop (g1)

What it shows

  • Listeners answered in 16, 9 and 22 seconds; the loop in 27, 42 and 26. On average 16 against 32.
  • In the loop, each slow triage (15 seconds) held up the scan and the alerts behind it; as a listener it held up only itself.
  • Both said each thing once, and left the passed scan alone.
  • The hub was off, since GitHub can't reach a laptop: every poll was a read answered at once, 304 while unchanged. With webhooks, a held read comes back as soon as GitHub says what changed.
