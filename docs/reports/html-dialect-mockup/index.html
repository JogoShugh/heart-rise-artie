A HEART resource, opened in a plain browser

What the HEART GitHub gateway would send a browser if it also spoke HTML. The branch, the draft pull request, their acts and their reasons were read from the running gateway on October 30, 2026. The HTML, the dialogs and the simulated answers are the proposal.

Commit a file, in a dialog

The act changes something, so it opens a dialog over the branch. The fields come from the act's JSON Schema. The branch is bound from the state, so it is not asked for. Try it in step 1's view: press "Commit a file", then pick an answer to simulate.

htmx sends

PUT /repos/JogoShugh/heart-github-test/branches/deps%2Fleft-pad-1.0.43-1030-175546/actions/commit-file HTTP/1.1
If-Match: "seq-0.hsf.L0.146b337830edd41b"
Accept: text/html
HX-Request: true
Content-Type: application/x-www-form-urlencoded

path=NOTES.md&message=Note+the+left-pad+bump&content=left-pad+1.0.43+is+pinned+until+the+tests+pass.%0A

A browser form sends strings. heart-core turns them into JSON by the act's schema before its usual checks, so the act pipeline sees exactly what an agent would send:

{ "path": "NOTES.md", "message": "Note the left-pad bump", "content": "left-pad 1.0.43 is pinned until the tests pass.\n" }

The gateway sends GitHub

PUT https://api.github.com/repos/JogoShugh/heart-github-test/contents/NOTES.md
{ "message": "Note the left-pad bump",
  "content": "bGVmdC1wYWQgMS4wLjQzIGlzIHBpbm5lZCB1bnRpbCB0aGUgdGVzdHMgcGFzcy4K",
  "branch": "deps/left-pad-1.0.43-1030-175546" }

The gateway answers the browser

HTTP/1.1 200 OK
Content-Type: text/html; charset=utf-8
HX-Trigger: {"heart:done": "Committed NOTES.md."}

<main id="resource" data-etag='"seq-1.hsf.L0.…"'> …the branch, read again… </main>

htmx swaps the fresh branch in place. The dialog closes and the status line says "Committed NOTES.md." for screen readers and eyes alike. The new ETag goes to every form.

GitHub refuses

HTTP/1.1 422 Unprocessable Entity
{ "message": "Invalid request.\n\n\"sha\" wasn't supplied.", "status": "422" }

NOTES.md already exists on the branch. GitHub only replaces a file when it is told the old file's sha, and this act has no such field.

The gateway answers the browser

HTTP/1.1 422 Unprocessable Content
Content-Type: text/html; charset=utf-8

<div class="problem" role="alert">
  <strong>GitHub refused the commit.</strong>
  <p>Invalid request. "sha" wasn't supplied.</p>
</div>

htmx's responseHandling setting lets a 422 swap into the dialog's problem slot. The dialog stays open with the person's text kept. The words are GitHub's, which is honest but not helpful (finding 5).

Someone pushed to the branch meanwhile

HTTP/1.1 412 Precondition Failed
Content-Type: text/html; charset=utf-8

<div class="problem stale" role="alert">This branch changed since you opened it.</div>

What heart-forms.js does next

GET /repos/JogoShugh/heart-github-test/branches/deps%2Fleft-pad-1.0.43-1030-175546
Accept: text/html

200 OK, ETag: "seq-2.hsf.L0.…"   → still offers github:commit-file
                                  → dialog stays open, fields kept, new If-Match
                                  → "This branch changed since you opened it. Check it, then commit again."

If the act were no longer offered, the dialog would close and the button would show the server's reason instead.

Open a pull request, as a draft

Same dialog shape. The draft field is a boolean, so it renders as a checkbox. A 201 moves the browser to the new pull request. Here GitHub would refuse, because this branch already has one: #1873.

htmx sends

POST …/branches/deps%2Fleft-pad-1.0.43-1030-175546/actions/open-pull-request HTTP/1.1
If-Match: "seq-0.hsf.L0.146b337830edd41b"
Content-Type: application/x-www-form-urlencoded

title=Bump+left-pad+to+1.0.43&base=deps-main&draft=on

An unchecked box sends nothing and a checked one sends on. The schema says boolean, so heart-core reads on as true and absence as false.

The gateway answers the browser

HTTP/1.1 422 Unprocessable Content
Content-Type: text/html; charset=utf-8

<div class="problem" role="alert">
  <strong>GitHub refused the pull request.</strong>
  <p>A pull request already exists for JogoShugh:deps/left-pad-1.0.43-1030-175546.</p>
</div>

The gateway answers the browser

HTTP/1.1 201 Created
Location: /repos/JogoShugh/heart-github-test/pulls/1874
HX-Location: {"path": "/repos/JogoShugh/heart-github-test/pulls/1874", "target": "body"}

The number is illustrative. HX-Location makes htmx load the new pull request as a real navigation: new address in the bar, back button works. Without htmx, the same answer is a 303 See Other to it.

The pull request's hr:unavailable link, followed (real answer)

GET /unavailable/…

{ "unavailable": [
    { "rel": "/profiles/github#reopen", "title": "Reopen",
      "reason": "The pull request is already open." },
    { "rel": "/profiles/github#merge",  "title": "Merge",
      "reason": "A draft can't be merged; mark it ready for review first." } ] }

The HTML dialect reads this on the server and writes the greyed buttons into the answer. The browser never follows the link itself.

A greyed act

<button data-rel="github:merge" aria-disabled="true"
        aria-describedby="why-merge">Merge</button>
<p id="why-merge" class="reason" hidden>A draft can't be merged; mark it ready for review first.</p>

aria-disabled, not disabled: the button stays focusable, so keyboard and screen-reader users reach it and hear the reason. Pressing it shows the reason as visible text; it never sends anything. An act the server neither offers nor explains gets no button at all.

What the mockup turned up

Each came from the real answers above. The questions are yours to decide.

1. How does a browser sign in to the gateway?

The gateway calls GitHub as each caller, with the caller's own token. An agent sends the token itself. A browser can't. Options: a "Sign in with GitHub" flow that sets a session cookie, or a token pasted once into a sign-in form.

Which, for the gateway? The garden slice keeps Basic sign-in either way.

2. Merge says "mark it ready for review first", but nothing offers that.

The draft's acts are Comment, Edit, Label, Request a review, Update the branch and Close. None marks it ready. GitHub's REST API has no such operation; only its GraphQL API does. In a browser this is a dead end, plainly visible.

Change the reason's words, or add a "Mark ready for review" act through another route?

3. Lists carry only titles.

The pull requests list has a title per item and nothing else, so the grid can't show state, draft or author columns.

Have the gateway embed each item's state in its lists (GitHub's list answer already holds it), or keep lists as titles?

4. A pull request has 36 state members.

Showing all is noise; choosing some is a view hint. The mockup shows 12 members, folds the other 22 behind "Show 22 more", and never shows hr:address, which is protocol, not state for a person.

Is "first 12 scalars, rest folded" the right generic default until view hints exist?

5. Field labels and help came from GitHub's own words. Fixed.

Commit a file's path was described only as "path parameter", base in three sentences, and no field had a title. Now every field has a title: the connector's own words first, then the operation's title, then the name split at underscores, hyphens and capitals (team_reviewers is "Team reviewers"). The dialogs above show the new words, read live from the gateway. The state's labels follow the same convention (changed_files shows as "Changed files"), with the member's own name kept on hover.

6. Base is free text.

The person types "deps-main" by hand. A choice of the repository's branches is exactly what the parked hr:options plan would give: choices from another resource.

Leave as text for the first slice?

7. "Reopen: already open" adds a greyed button that says the obvious.

Stable slots are good, but a reason that only restates the state is clutter.

Show every listed act greyed, or let the connector mark some reasons as not worth a button?

8. The branch links nowhere back.

Its links are GitHub, protection and self. No link up to the repository or its branches, so the only way back is the browser's Back button.

Add an up link to branches (and pull requests) in the connector?

9. Commit a file can't replace a file.

GitHub needs the old file's sha to replace one, and the act has no such field, so a second commit to the same path is refused with GitHub's words.

Out of scope for HTML; note it for the gateway?
