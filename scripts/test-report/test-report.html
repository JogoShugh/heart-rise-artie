What changed to get here

Fixes made in this pass

  • Affordance-set URLs now match the bytes served. The server used to hash the canonical JSON but send Jackson's output, which has keys in a different order. It now sends the canonical string. (SPEC §6.5)
  • HAL-FORMS fields are fillable again. depthCm and milliliters were marked readOnly: true because the request DTOs used val. They now use var.
  • Client test tightened. The "unknown action" test used to pass even if the client called the network. It now also checks that no request was sent.
  • Koog exhibit compiles again. Its tests used a removed UniformArgs wrapper, so they were updated to pass a plain JsonObject.
  • The test that copied production code is gone. It was replaced by real HTTP checks.
  • Cache-demo fixtures regenerated. They are now canonical JSON from a fixed random seed, so regenerating gives identical files.

Example: each affordance-set URL is the sha256 of the bytes served at it

Rule
SPEC §6.5: the hash in /affordance-sets/sha256-… identifies the actual bytes at that URL. A client or cache can verify a response by hashing it.
How
@WebFluxTest starts only the two controllers, with no database. For each of the 3 bed statuses, the test GETs the URL over the test HTTP client, hashes the raw response body, and compares that hash to the URL. It doesn't reuse any production hashing code, so the test can't agree with a bug just because both share the same helper.
Real data
From the live capture, /affordance-sets/sha256-14707229191a4566 serves:
{"_forms":{"sowSeed":{"_links":{"target":{"href":"/beds/{bedId}/actions/sow-seed","templated":true}},"contentType":"application/json","method":"POST","schema":{"$id":"/schemas/sha256-4ed779d47421af87"}}}}
The keys are sorted (contentType before method) with no whitespace. That is the RFC 8785 canonical form.

Before the fix, this test failed (line 54). The server was sending Jackson's insertion-order JSON, and those bytes hashed to dd9a1964d19f5485, not the 14707229191a4566 in the URL.

The fix: AffordanceSetController now returns JsonSchemaDialectSupport.affordanceSetJson(...), the canonical string, instead of a Map. The test passes.

Example: acting on an action absent from the manifest raises an error

Rule
This is H.E.A.R.T.'s core guarantee: the agent can only act on what the server offered. Here, the server offered transition and the caller asks for nonexistent.
How
A fake transport returns one canned response for enter. The test then calls act("nonexistent", …) and checks two things: an error was raised, and the fake transport recorded zero submits.
Why both
The fake transport throws when its queue is empty. So "an error was raised" alone would also pass if the client had wrongly tried the network. The second check closes that gap.

Mutation check: I temporarily made act call the transport before checking the manifest. The scenario failed with Expected no submit, but got [POST https://example.com/nonexistent]. I then restored the original code.

Example: journal entry 02 — the watering form must be fillable

Rule
In the HAL-FORMS dialect, a field marked readOnly: true tells clients not to fill it in. If milliliters can't be filled in, the agent can't water the bed.
Cause
Spring HATEOAS reads a Kotlin val (getter but no setter) as read-only (Spring HATEOAS issue #1310).
Before
The journal committed in July already showed this entry as FAIL — regression detected, and the first run in this pass reproduced it. The new unit test RequestDtoMetadataTest failed for both DTOs: WaterCellRequest.milliliters is readOnly and SowSeedRequest.depthCm is readOnly. The second one was never covered by the journal.
After
With the DTOs changed to var, the unit test passes, no captured response contains readOnly, and journal entry 02 shows Correct.
